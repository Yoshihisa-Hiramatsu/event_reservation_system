# LINE予約管理システム v2（GASコード）導入手順

v1からの主な変更点

- 複数の開催を同時に募集できます（LINEで番号を選んでもらいます）
- 質問文・項目名・使う/使わない（ON/OFF）・返信メッセージを、開催シートの「設定」タブで変えられます
- 業種別のひな形が4種類（美容／見学会・デモ／個別相談会／パーティ（最小構成））
- 満席のときは「要確認（キャンセル待ち）」として受け付けるか、受け付けずに枠を隠すかを、設定タブで切り替えられます
- 選んだ枠で対応できる人だけを選択肢に出せます
- キャンセル・変更は、予約の一覧から番号または名前で選びます。変更は複数の項目をまとめて行えます
- LINEの「空き枠確認」で、開催の空き状況（残り人数・満席）を確認できます
- 登録の途中で「やめる」ボタンで中止できます
- 同じ枠で同じ対応者を希望する人が重なったときに、「担当者が変わる可能性があります」と知らせます
- 主催者は、LINEで「通知登録 合言葉」と送って、通知先に自分で登録できます
- 親シートのメニューから、ひな形を複製して新しい開催を作れます
- 当日スケジュール・要確認リストの作成も親シートのメニューに移りました（開催別シートにGASは不要です）

## 1. コードを親シートのApps Scriptに作る

これまで開催別シート側のApps Scriptに入れていたコードは、**親シートのApps Scriptにまとめます**。
親シートにApps Scriptがまだない場合は、新規作成になります。

1. 親シート（開催マスタが入っているファイル）を開き、「拡張機能」→「Apps Script」
2. 最初からある `コード.gs`（空の関数）は削除してかまいません
3. 次の16ファイルを、同名で作って貼り付けます（「+」→「スクリプト」）
   `Config.gs` `Util.gs` `Settings.gs` `StateManager.gs` `LineApi.gs` `SheetUtils.gs` `EventSelector.gs`
   `Identity.gs` `RegisterFlow.gs` `CancelFlow.gs` `ConfirmFlow.gs` `ChangeFlow.gs` `AvailFlow.gs` `EventAdmin.gs` `Menu.gs` `Main.gs`
4. 「プロジェクトの設定」（歯車）→「スクリプト プロパティ」に2つ追加
   - `CONTROL_SHEET_ID` : **親シート**のスプレッドシートID（URLの `/d/` と `/edit` の間）
   - `LINE_CHANNEL_ACCESS_TOKEN` : これまでと同じトークン（旧プロジェクトの同じ画面からコピーできます）
5. 「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」→実行ユーザー「自分」・アクセスできるユーザー「全員」→デプロイ
   初回は権限の承認が出ます。表示された**新しいURL**をコピーします
6. LINE Developersの「Messaging API設定」で、Webhook URLを**新しいURLに置き換え**、「検証」を押して成功を確認します
7. 親シートを再読み込みすると、上部に「予約管理」メニューが出ます

以後のコード修正は、コードを貼り替えて「デプロイ」→「デプロイを管理」→鉛筆アイコン→
バージョン「新しいバージョン」→「デプロイ」で反映します（この場合はURLが変わりません）。

旧プロジェクト（開催別シート側）のWebhookは、手順6で切り替えた時点で使われなくなります。
新しい方で動作確認ができるまでは、旧プロジェクトを消さずに残しておいてください。

## 2. ひな形を登録する

1. 4つのxlsx（美容／見学会デモ／個別相談会／パーティ）をGoogleドライブにアップロードし、Googleスプレッドシートとして開いて保存します。
2. 親シートに「ひな形」タブを作り、次のように入力します（A1=ひな形名、B1=URL）。

   | ひな形名 | URL |
   |---|---|
   | 美容イベント | （美容のスプレッドシートのURL） |
   | 見学会・デモ | （〜） |
   | 個別相談会 | （〜） |
   | パーティ（最小構成） | （〜） |

## 3. 開催を作る

1. 親シートを開き直し（再読み込み）、上部メニュー「予約管理」→「新しい開催を作成（ひな形から複製）」
2. 開催日 → 開催名 → ひな形の番号を入力
3. 初回は権限の承認（Googleドライブへのアクセス）が出るので承認し、もう一度メニューを実行
4. 親シートと同じフォルダに `開催年月日_開催名` のファイルができ、開催マスタに追記されます（ステータスは「準備中」）
5. 新しいファイルの「設定」「対応者一覧」「枠マスタ」「メニュー」を入力
6. 準備ができたら、開催マスタのステータスを「募集中」にする

## 4. 「設定」タブ

列：A=内部キー（変更しない）／B=表示名／C=LINEの質問文／D=使う(ON/OFF)／E=選択肢／F=補足（読まれません）

- C列が空欄、または「…」で終わる文は「未設定」とみなし、標準の質問文になります
- `guest`（ゲスト）は必須で、OFFにしても無効です
- `slot`（時間枠）をOFFにすると、時間枠を聞きません。このとき「枠マスタ」の受付可能人数の**合計がイベント全体の定員**になります（受付可能人数が空欄なら制限なし）。「当日スケジュール」は、招待者ごとの参加者名簿として作られます
- `waitlist`（満席でも受け付ける）：**ON**＝満席の枠も選べて、キャンセル待ち（要確認）で受け付けます。**OFF**＝満席の枠は選択肢に出さず、全部満席なら受付終了メッセージ（`msg_closed`）を返して終わります。行が無ければONとして扱われます
- `msg_full` は、ONで全部の枠が満席のとき、登録を始める前に聞く文です（このあと［進める］［やめる］が出ます）
- `msg_overlap` は、同じ枠・同じ希望対応者の予約がすでにあるときの注意文です（`{staff}` は対応者名）
- `note`（伝えておきたいこと）・`age`・`gender`・`staff`・`menu`・`organizer` も、D列をOFFにすると質問を飛ばします。**設定タブに行が無い項目は、ONとして扱われます**（OFFにしたい項目は、行を足してください）
- `organizer` をOFFにすると、動員する人を聞かず、予約タブの「動員する人」の列は空欄のまま、ゲスト本人の名前だけで予約・キャンセル・変更を探します
- `staff` のE列は「対応者一覧の最後に付ける選択肢」（例：誰でも良い）
- `note` のE列の先頭は「特になし」に当たる言葉（これが選ばれたら空欄で保存）
- `msg_accepted` `msg_pending` は返信メッセージ。`{no}` は予約番号に置き換わります
- 表示名を変えたら、メニュー「予約タブの見出しを設定に合わせる」で予約タブの見出しも更新できます
- 設定タブが無い古い開催シートも、標準の文言（美容版）のまま動きます
- **設定が反映されないとき**：親シートのメニュー「予約管理」→「設定の読み込みを確認」で、LINEのBotが読んでいるファイル名と、読み取った内容（ON/OFF・質問文）を確認できます。Botが読むのは、**開催マスタの「予約シートURL」で開くファイル**の設定タブです（ひな形そのものではありません）
- 「動員する人」の質問文は、初めて名前を聞くときだけ使われます（2回目以降は「前回『○○』として登録されていますが…」と聞きます）

## 5. 定員と「キャンセル待ち（要確認）」

設定タブの `waitlist`（満席でも受け付ける）で動きが変わります。

- **ON（標準）**
  - 一部の枠だけが満席：満席の枠も選択肢に出し、質問の下に「※『午前』はキャンセル待ち（要確認）での受付になります。」と添えます。満席の枠を選ぶと、確認画面にも注記が出て、**その枠つきの「要確認」**で登録します
  - すべての枠が満席：登録を始める前に「現在は満席です。キャンセル待ち（要確認）としての登録になりますが、登録を進めますか？」と聞きます（［進める］［やめる］）。進めた場合は、**時間枠なしの「要確認」**として登録します
  - 時間枠をOFFにしている開催：全体の定員に達していれば、同じく最初に聞いて「要確認」として登録します
- **OFF**
  - 満席の枠は選択肢に出ません。すべて満席なら、受付終了メッセージを返して、登録は始まりません
- 変更フローで枠を変えるときは、ON/OFFにかかわらず、空きのある枠だけを出します
- 受付可能人数が空欄の枠は、人数の制限なしとして扱います
- キャンセルが出ても、「要確認」の人は自動では繰り上がりません。キャンセル時の主催者への通知に「要確認の予約が○件あります」と出るので、予約タブでステータスを「受付」に直してください
- 「要確認」の人も定員の人数に数えます（キャンセルが出たとき、待っている人より先に新しい人が入らないようにするためです）

## 5-3. 同じ枠・同じ対応者の重なり

同じ枠で、同じ「希望する対応者」の予約がすでにあるとき（キャンセル済みは数えません）、登録・変更の確認画面と完了メッセージに「※この枠の『○○』さんは、すでに他の方のご希望があります。担当者が変わる可能性があります。」と出し、主催者への通知にも⚠を付けます。「誰でも良い」のような末尾の選択肢は対象外です。予約タブの「重複チェック」列にも「⚠重複あり」が出ます。

## 5-2. 枠ごとに対応できる人を絞る
対応者一覧の **B列（対応可能時間帯）** に、枠マスタの「枠名」をカンマ（, 、 ，）区切りで書くと、その枠を選んだときだけ候補に出ます。
- 例：江藤＝`10時枠、11時枠` → 「10時枠」を選んだ人には江藤さんだけが出る（「朝1」「昼2」のような枠名でも同じ）
- 枠名は枠マスタと**同じ文字**で書いてください（「10時枠」と「10時」は別物）
- B列が空欄の人、または枠名が1つも書かれていない人（「午前のみ」などのメモ）は、どの枠でも選べます
- その枠で対応できる人が1人もいないときは、希望対応者の質問は飛ばします
- 時間枠を使わない開催・キャンセル待ち（枠なし）のときは、全員が候補になります
- 登録だけでなく、変更フローで対応者を変えるときも、予約の枠に合わせて絞ります

## 6. 複数開催のLINEでの流れ

- 募集中が2件以上のとき、「登録」「キャンセル」「登録確認」「変更」「空き枠確認」を送ると、最初に開催を番号で選びます
- 募集中が1件だけなら、選択は飛ばして進みます
- 同時に選べるのは12件までです（LINEのボタンが13個まで）

## 6-2. キャンセル・変更・登録確認のLINEでの流れ

- **キャンセル**：予約した人の名前を伝える → その人の予約の一覧（キャンセル済みは出ません）→ 番号（「2」「No.2」）または名前を入力 → 登録内容つきの確認 → 「キャンセルする」
- **変更**：同じく一覧から予約を選ぶ → 登録内容が表示される → 変更する項目（時間枠／希望対応者／メニュー／年齢／性別／伝えておきたいこと。設定でONのもの）を選んで新しい内容を入力 → 「他に変更する項目はありますか？」（何回でも）→ 「ない（確認へ進む）」→ 変更後の内容つきの確認 → 「この内容で変更」
- 時間枠を変えるときは、空きのある枠だけが選べます。希望する対応者が新しい枠に対応できないときは、選び直してもらいます
- 同じ名前の予約が複数あるときは、番号で選んでもらいます
- 「動員する人」をOFFにした開催では、動員する人ではなく、ご本人（ゲスト）の名前を聞いて一覧を出します
- 登録確認：予約した人の予約を一覧で表示します
- 変更の項目選択画面にも「やめる」があります

## 6-3. 空き枠確認・登録の「やめる」・通知先の登録

- **空き枠確認**：LINEで「空き枠確認」と送ると、枠ごとの残り人数（満席の枠は「満席」）を返します。時間枠をOFFにした開催は、全体の残り人数です。リッチメニューを使っている場合は、ボタンを1つ足して、送る文字を「空き枠確認」にしてください
- **やめる**：登録の途中（名前・時間枠・年齢・性別・対応者・備考）に「やめる」ボタンが出ます。押すと登録を中止し、何も保存しません。メニュー選択の画面はボタンの余裕がないため、「やめる」と文字で入力したときだけ中止できます
- **通知先の登録**：親シート「主催者通知先」タブのD列に「合言葉」の見出しを作り、D2に合言葉を決めて入力します。通知を受け取りたい人が、公式アカウントを友だち追加したうえで「通知登録 合言葉」と送ると、LINE User IDと表示名が自動で追記されます。やめるときは「通知解除」（通知ON/OFFがOFFになります）。合言葉が空欄の間は使えません。手でLINE User IDを書いても構いません

## 7. 当日スケジュールと要確認リスト

1. 前日ミーティングで、予約タブの「確定担当者」「確定枠番号」を埋める
2. 親シートのメニュー「予約管理」→「当日スケジュールと要確認リストを更新」→開催を選ぶ
3. 同じ担当者・同じ枠に複数ゲストがいるセルはオレンジ色になり、件数が表示されます
4. 要確認リストには、ステータスが「要確認」の予約が並びます

## 8. 旧ひな形について

旧「予約管理_開催別ひな形」にGASを入れていた場合、そのGASプロジェクトは不要です。
複製すると一緒に複製されてメニューが二重に出るため、旧ひな形のApps Scriptは削除してください。
すでに動いている開催シートは、そのまま使えます（予約タブの列位置は変わっていません）。

## 9. 変更・修正のメモ

- 予約タブは「見出しの文字」ではなく「列の位置」で読むようになりました。見出しは自由に変えられますが、**列の順番は変えないでください**
- 対応者一覧・メニューも1列目（A列）を読みます。見出しの文字は自由です
- 「要確認」の予約を変更しても、ステータスが「変更済」に上書きされず「要確認」のままになります
- クイックリプライは13個までのため、メニューは12項目まで・時間枠と対応者は12個までが目安です（「やめる」ボタンの分）
- 処理は1件ずつ順番に行い、LINEの再送は2回処理しません。処理中に例外が出たときは「うまく処理できませんでした。もう一度お送りください」と返し、親シートのApps Scriptの「実行数」にエラーが残ります

## 既知の制限

- 会話状態は30分操作がないと消えます（`Config.gs` の `STATE_CACHE_SECONDS`）
- 同じ名前のゲストを同じ動員者が2人登録しても、番号を入力すれば区別できます（名前で入力すると、番号を聞き直します）
- 「要確認」の人の繰り上げは手動です（予約タブでステータスを「受付」に直します）
- 登録確認の画面は、キャンセル・変更の一覧とは別の表示形式です
- 「動員する人」をOFFにする前の旧データ（動員する人の列に本人の名前が入っているもの）も、ゲスト名で探せるため、そのまま使えます
- 前回の名前（「前回『○○』として登録されていますが…」）は、LINEユーザーごとにApps Scriptのスクリプトプロパティに保存されます。LINEアカウントを共有している場合は、［いいえ］で入れ替えられます
