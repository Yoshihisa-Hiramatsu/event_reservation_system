# LINE予約管理システム（GASコード）セットアップ手順

## 前提

- 親（コントロール）シート・開催別ひな形（対応者一覧／枠マスタ／施術メニュー／予約 の各タブ）は作成済みであること
- 開催マスタの該当行の「ステータス」が「募集中」になっていること
- LINE公式アカウント（Messaging API）のチャネルが作成済みであること

## 1. スクリプトの配置

1. 親（コントロール）シートを開く
2. 「拡張機能」→「Apps Script」
3. `Config.gs` `Main.gs` `StateManager.gs` `LineApi.gs` `SheetUtils.gs`
   `RegisterFlow.gs` `CancelFlow.gs` `ConfirmFlow.gs` `ChangeFlow.gs`
   の内容をそれぞれ同名のファイルとして貼り付ける
   （スクリプトエディタの「+」→「スクリプト」でファイルを追加してください）

## 2. スクリプトプロパティの設定

スクリプトエディタ左側の「プロジェクトの設定」（歯車アイコン）→
「スクリプト プロパティ」で以下を追加します。

| プロパティ名 | 値 |
|---|---|
| `CONTROL_SHEET_ID` | 親シートのスプレッドシートID（URLの `/d/` と `/edit` の間の文字列） |
| `LINE_CHANNEL_ACCESS_TOKEN` | LINE Developersコンソールで発行したチャネルアクセストークン（長期） |

## 3. Webアプリとしてデプロイ

1. スクリプトエディタ右上「デプロイ」→「新しいデプロイ」
2. 種類の選択で「ウェブアプリ」を選択
3. 実行ユーザー：「自分」
4. アクセスできるユーザー：「全員」
5. デプロイ後に表示されるURLをコピー

## 4. LINE DevelopersでWebhookを設定

1. Messaging APIチャネルの設定画面を開く
2. 「Webhook URL」に手順3のURLを貼り付け
3. 「Webhookの利用」をONにする
4. 「応答メッセージ」はOFFにしておく（自作の応答と競合するため）

## 5. 主催者のLINE User IDを取得

主催者通知先タブの「LINE User ID」は、以下のいずれかで取得できます。

- 一時的に `Main.gs` の `handleTextMessage` の先頭に
  `console.log(userId);` を追加し、主催者本人にメッセージを送ってもらって
  実行ログ（表示→ログ）から確認する
- もしくは、あとで「友だち追加時に自動でIDを控える」処理を追加することも可能です

確認できたら、忘れずにログ出力用のコードは削除してください。

## 6. 動作確認

1. 開催マスタの対象行のステータスが「募集中」になっていることを確認
2. LINEで「登録」と送信し、一連の質問に答えて登録が完了するか確認
3. 予約タブに正しく1行追加されているか確認
4. 主催者通知先に登録したLINE User IDに通知が届くか確認

## 7. 当日スケジュールの作成（Menu.gs）

`Menu.gs` は「**開催別ひな形**」のスプレッドシート（対応者一覧・枠マスタ・予約タブ
などが入っているファイル）に貼り付けるコードです。親シートではなく、こちらの
GASプロジェクトに追加してください。同じプロジェクトに他の9ファイルも一緒に
入っている場合は、そのまま`Menu.gs`を追加するだけで大丈夫です。

貼り付けたら、一度スプレッドシートを開き直す（またはブラウザを再読み込みする）と、
上部メニューに「**予約管理**」という項目が追加されます。

使い方：

1. 前日ミーティングで、予約タブの「確定担当者」「確定枠番号」を埋める
2. スプレッドシート上部の「予約管理」→「当日スケジュールを作成・更新」を実行
3. 初回実行時は権限の承認を求められるので、承認して進める
4. 「当日スケジュール」タブが、対応者一覧・枠マスタの最新の内容で作り直され、
   確定担当者・確定枠番号が入っている予約が反映される
5. 1人の対応者が同じ枠で複数のゲストを担当している（重複している）セルは、
   自動的にオレンジ色で色分けされる
6. 実行後、重複件数を知らせるメッセージが表示される

対応者や枠を追加・変更した後も、再度メニューを実行すれば表が作り直されるので、
手作業でのメンテナンスは不要です。

## 既知の制限・今後の拡張ポイント

- 会話状態は30分操作がないと自動的に消えます（`Config.gs` の `STATE_CACHE_SECONDS` で変更可）
- 現在は「募集中の開催は常に1つ」という前提です。同時に複数の開催を扱う場合は
  `SheetUtils.getActiveEvent` の拡張が必要です
- 「開催シートの自動作成（複製）」「要確認リストの自動抽出」は今回まだ未実装です。
  「要確認リスト」タブも、当日スケジュールと同じ考え方（ステータス＝要確認の行だけを
  自動抽出する）で今後追加できます
